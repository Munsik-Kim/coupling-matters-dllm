# 에이전트 평가 후속 연구 동결 기록

2026년 11월 26일 · CPU 검증 완료 · 에이전트 응용을 위한 신규 dLLM GPU 실험 보류

각 정책이 혼자 업무에 성공할 확률은 그 정책과 환경이 결정한다. 각 정책의 실행 확률을 보존하면서 두 결과를 짝짓는 규칙을 바꾸면 같은 성공률 차이를 얼마나 정밀하게 잴 수 있는지, 어느 단계가 먼저 달라져 보이는지가 달라진다. 이번 후속 연구는 그 차이가 평가 비용 절감이나 수정 우선순위 선정에 도움이 되는지 점검했다. [한국어 보고서 PDF · 8쪽](Coupling_Matters_Agent_Report_KO.pdf) · [본문과 표](Coupling_Matters_Agent_Report_KO.md)

## 동결 판단의 근거

| 자료 | 확인한 결과 | 해석 범위 |
|---|---|---|
| 기존 Coupling Matters | 이미 확정된 토큰을 계속 복사하는 생성 과정에서는 처음 분기할 때 남은 빈칸의 비율로 최종 토큰 불일치를 상계할 수 있다. | 고정된 토큰 거리와 생성 조건에 관한 결과다. 도구 호출의 의미와 업무 성공에는 별도 채점이 필요하다. [원 연구의 한계](../../docs/LIMITATIONS.md) |
| Case017 공개 원장 | 같은 24개 과제에서 자유 생성에 출력 문법을 적용하자 검증된 업무 완료가 7→15건, 올바른 저장 상태가 7→22건, 최신 상태 검증 관측이 7→16건이었다. 세 지표 모두 손실은 0건이었다. | 양쪽 가중치는 BF16이고 KV 정밀도는 NVFP4로 고정했다. 개발 단계 확장 기준에 미달한 탐색적 자기회귀 모델 실험이다. 최신 상태 검증 관측은 사후 지표다. [원 실험 보고서](https://github.com/Munsik-Kim/inference-lab/blob/9ca5eee3da47c552f02d7eaa7b7a6393fb3f2d17/cases/017-agent-contract-cost-bench/REPORT.md) |
| 유한 에이전트 정확 계산 | 세 규칙에서 업무 성공률 차이는 모두 +5/64였다. 한 쌍에서 계산한 성공 여부 차이의 분산은 공통 Gumbel 난수로 짝지으면 독립 표집의 54.1%, 각 단계에서 행동을 최대한 일치시키면 40.1%였다. 다른 모형에서는 첫 도구를 일치시키면 분산이 독립 표집의 두 배가 됐다. | 지정한 유한 모형의 결과다. 실제 dLLM에서의 평가 비용과 정밀도는 측정하지 않았다. [정확 계산](coupling_agent_exact.json) · [반례](counterexamples.json) |

**수정을 어디에 할 것인가.** 첫 도구가 달라진 경로들의 순기여는 +1/64였지만 A의 도구 선택 규칙만 B의 것으로 교체했을 때 성공률 변화는 0이었다. B의 한 단계를 같은 비용으로 완전히 교정하는 별도 비교에서, 최초 분기 기준이 선택한 인자 교정의 이득은 +3/64, B 자체의 오류율 기준이 선택한 도구 교정의 이득은 +27/64였다. 관측한 분기에서 수정의 효과를 추론하려면 실제 개입과 재평가가 필요하다.

**남은 이론적 관찰.** 성공률이 각각 1/2인 다른 모형에서는 최종 결과만 보고 짝지으면 회복과 손실을 모두 0으로 만들 수 있다. 각 시점에서 상대의 과거를 보더라도 자기 정책의 다음 선택 확률을 지키도록 하면 이 모형의 모든 허용 규칙에서 회복과 손실이 각각 1/4이다.

## 어떤 근거가 생기면 재개하는가

분기별 선택 확률과 후속 행동을 재생할 수 있는 자료가 생기면 아래 두 조건 중 하나를 확인한다.

1. 별도 평가 과제에서 같은 비용으로 수정 하나를 적용했을 때 커플링 진단이 통상적인 단계별 오류율 기준보다 더 큰 업무 개선을 고른다. 잘못된 상태 변경도 함께 채점한다.
2. 같은 성능 차이를 측정할 때 기록·동기화·재생 비용을 포함한 동일 총예산에서 추정 오차가 줄어든다. 필요한 이득과 허용 비용은 평가 전에 정한다.

양자화 후에 정상 실행되지만 사용자 의도에 어긋난 도구·인자가 더 자주 나오는지는 별도의 품질 질문으로 보존한다. 이 동결은 에이전트 응용의 계산 투자에 관한 결정이다. 원 논문의 수송 상한과 기존 실험의 근거는 [공개 기준 버전](https://github.com/Munsik-Kim/coupling-matters-dllm/tree/c6632d5879a84ff135c8f717aad33a03a1a0cfeb)에 있다.

## CPU 재현

저장소 최상위에서 다음 명령을 실행한다.

```sh
python3 followups/2026-11-26-agent-coupling/run_checks.py
```

표준 라이브러리만으로 단독 정책별 12개 경로, 규칙별 144개 경로 쌍, 단계 교체와 반례를 다시 계산하고 보관된 결과와 비교한다. 세 번째 검사는 공개 원장에서 추린 24개 과제 쌍을 다시 집계한다. 256행짜리 원장 자체에서 같은 파일을 복구하는 명령과 원장의 SHA-256은 [재현 안내](README_KO.txt)에 있다.
